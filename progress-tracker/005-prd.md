# Product Requirements Document (PRD)

## Problem Statement
ABC Ltd., an organization with multiple departments, lacks a centralized, professional, and user-friendly system to track the progress of tasks across its various teams. Currently, managers and employees struggle to have a clear, real-time view of task statuses, assignments, and deadlines, leading to potential inefficiencies and communication gaps.

## Solution
A web-based progress tracker application specifically designed for ABC Ltd. The application will provide distinct roles for managers and employees, enabling organized task management within departments. Built with a modern tech stack (React, Vite, Bootstrap) and powered by Supabase, it will offer a secure and efficient way to create, track, and update tasks in a professional, "siloed" environment that ensures users only see what is relevant to them.

## User Stories
1. As an **Admin**, I want to create and name new departments, so that the organizational structure is centrally managed.
2. As an **Admin**, I want to create user accounts for managers and employees and assign them to specific departments, so that access is properly controlled.
3. As a **Manager**, I want to create tasks within my department, so that I can organize my team's workload.
4. As a **Manager**, I want to assign a single owner to each task, so that there is clear accountability.
5. As a **Manager**, I want to set optional due dates for tasks, so that time-sensitive work is prioritized.
6. As a **Manager**, I want to set priority levels (High, Medium, Low) for tasks, so that the team knows what to focus on first.
7. As a **Manager**, I want to view all tasks within my department, so that I can monitor overall progress.
8. As a **Manager**, I want to update the status, priority, and owner of any task in my department, so that I can manage the workflow effectively.
9. As an **Employee**, I want to log in securely with my email and password, so that I can access my tasks.
10. As an **Employee**, I want to see a list of tasks assigned to me, so that I know what I need to work on.
11. As an **Employee**, I want to see other tasks within my department (Read-only), so that I have context on the team's work.
12. As an **Employee**, I want to update the status of tasks assigned to me (e.g., from "In Progress" to "Done"), so that my manager is informed of my progress.
13. As a **User**, I want to be restricted from seeing tasks or departments I am not assigned to, so that my workspace remains focused and private.
14. As a **User**, I want to see a clear visual indicator of task priority and status, so that I can quickly assess the task board.

## Implementation Decisions
- **Frontend Tech Stack:** React (Vite) for the UI framework and Bootstrap for styling and layout.
- **Backend & Database:** Supabase will provide the PostgreSQL database, Authentication, and Auto-generated APIs.
- **Authentication:** Supabase Email & Password authentication.
- **Data Model:**
    - **Departments:** Created only by Admins.
    - **Users:** Each user belongs to exactly one department.
    - **Tasks:** Each task belongs to one department and has exactly one owner (Employee).
- **Task Statuses:** A global fixed set (e.g., Pending, In Progress, Completed) to ensure consistency.
- **Task Priorities:** Standard levels (High, Medium, Low).
- **Visibility Logic:** Row-Level Security (RLS) in Supabase will enforce departmental silos, ensuring users only access data relevant to their assigned department.
- **Audit Logging:** Not required for the initial prototype; only the current state of tasks will be persisted.

## UI Aspects
- **Layout:** A responsive dashboard with a top navigation bar (branding, user profile, logout) and a sidebar for navigation (Tasks, Team, etc.).
- **Task Board:** A list or card-based view showing Task Name, Owner, Status (with color coding), Priority, and Due Date.
- **Task Modals:** Detailed views for creating and editing tasks, with clear validation for required fields.
- **Filters/Search:** Ability to filter tasks by status, owner, or priority within the department view.
- **Professional Aesthetic:** Clean, corporate look using standard Bootstrap components, with a focus on readability and clear call-to-action buttons.
- **Authentication Pages:** Dedicated Login page with error handling for incorrect credentials.

## Testing Decisions
- **Quality Standard:** Tests should verify the external behavior of core modules (e.g., Task management logic, Auth flow) rather than implementation details.
- **Modules to Test:**
    - **Auth Module:** Login/Logout flows and session persistence.
    - **Task Management:** CRUD operations for tasks, ensuring departmental boundaries are respected.
    - **Data Access Layer:** Verification of Supabase RLS policies to ensure departmental silos.
- **Testing Tools:** Vitest for unit/integration tests and React Testing Library for component testing.
