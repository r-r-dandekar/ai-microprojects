# Design to Code

**Phase:** Build
**Estimated Time Saved:** ~65%
**Software Solution:** ❌ No

---

## The Problem

Translating a Figma design into a production-ready React component is pure mechanical translation: matching hex codes, calculating spacing, building responsive breakpoints, and ensuring consistency with the project's design system. This "pixel pushing" work consumes a disproportionate amount of developer time, is error-prone (breakpoints are frequently missed on first pass), and produces inconsistent output when different developers style the same design. It is one of the highest-ratio tasks for manual effort vs. actual thinking required.

---

## AI-Native Workflow

> **Pipeline:** Figma design exported → v0.dev generates the component → Claude refines and connects to real data → developer reviews and ships

**Steps:**

1. ⚡ **Trigger** — Designer delivers a new screen or component in Figma
2. 👤 **Human Override Point** — Developer exports the design: screenshot, Figma frame link, or CSS/SVG export. Provides the project's `tailwind.config.js` and any existing base components.
3. 🤖 **AI** — v0.dev ingests the design image/description and generates a responsive React + Tailwind component matching the visual layout
4. 🤖 **AI** — Claude refines the v0 output: applies the project's specific theme tokens (colours, fonts, spacing from `tailwind.config.js`), adds interactive states (hover, focus, loading, error, empty), and ensures accessibility (ARIA labels, keyboard navigation)
5. 🤖 **AI** — Claude connects the component to the project's data layer: replaces static placeholder data with the correct props interface and connects to the relevant React Query hook or server action
6. 👤 **Human Override Point** — Developer reviews the component in the browser at mobile, tablet, and desktop breakpoints. Checks against the Figma design for fidelity. Approves and commits.

| Tool | Purpose |

## Prompt Templates

### Refine v0 Component for Production
```
You are a senior frontend developer at Alphonso Solutions.

I have a React + Tailwind component generated by v0.dev. Refine it for production use.

[PASTE v0.dev GENERATED COMPONENT]

Project theme config (tailwind.config.js):
[PASTE TAILWIND CONFIG]

Apply the following changes:
1. Replace all hardcoded colours and spacing values with the project's theme tokens
2. Add interactive states: hover, focus-visible, disabled, loading (skeleton), and empty state
3. Add ARIA labels and ensure keyboard navigation works correctly
4. Make the component fully responsive: mobile-first, with breakpoints at sm (640px), md (768px), lg (1024px)
5. Replace all static placeholder data with TypeScript props — define a fully typed Props interface
6. Add an optional className prop for extensibility

Do not change the visual design. Only apply the above changes.
```

### Connect Component to Data Layer
```
Connect the following React component to real data.

Component:
[PASTE COMPONENT]

Data source: [describe — e.g., "Supabase table 'products', fetched with React Query"]
Required data shape: [describe or paste the TypeScript type]

Generate:
1. The updated component with real data props wired in
2. The React Query hook (or server action for Next.js App Router) that fetches the data
3. Loading state handling using the existing skeleton pattern
4. Error state handling with a retry option
```

## Notes

- Always feed the project's `tailwind.config.js` to both v0.dev and Claude to avoid having to manually replace theme tokens after generation.
- For complex interactive components (drag-and-drop, rich text editors, date pickers), it is faster to find a headless library (Radix UI, shadcn/ui) and style it than to generate from scratch.
- Use Figma's Dev Mode (paid plan) to export exact spacing, colour, and typography tokens — paste these into the prompt for maximum fidelity.
