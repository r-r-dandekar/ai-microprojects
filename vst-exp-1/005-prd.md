# PRD: RD-Processor-Mk-01

## Problem Statement
Guitarists require a flexible, intuitive VST processor that allows for custom signal chain design, including serial, parallel, and complex routing, while maintaining low-latency real-time performance.

## Solution
RD-Processor-Mk-01, a VST 3 plugin providing a drag-and-drop, graph-based signal chain interface. It supports modular effects, sidechain-linked dynamics, and dynamic latency compensation, all managed through an MVC UI architecture.

## User Stories
1. As a guitarist, I want to add effects in a serial chain, so that I can define my basic signal flow.
2. As a sound designer, I want to split my signal path for parallel processing, so that I can blend processed and dry signals or multiple effect chains.
3. As a guitarist, I want to merge parallel signal paths, so that I can combine complex sounds into one output.
4. As a user, I want to drag and drop blocks within the signal path, so that I can easily reorder my effects.
5. As a guitarist, I want to use a compressor and decompressor, so that I can shape the dynamics of my performance.
6. As a user, I want to link a decompressor to a previously applied compressor's envelope, so that I can create dynamic frequency or level effects.
7. As a user, I want a minimalistic sidebar that shows only the parameters of the currently selected effect, so that I can focus on fine-tuning.
8. As a user, I want to load my own IR files for cabinet simulation, so that I can customize my tone.
9. As a musician, I want the plugin to automatically compensate for latency introduced by my effect chain, so that my DAW stays in sync.
10. As a user, I want an intuitive "Add Block" palette, so that I can quickly expand my signal chain.

## Implementation Decisions
- **Architecture:** MVC (Model-View-Controller) separation.
- **Audio Traversal:** Push/Pull graph traversal during `processBlock`.
- **Latency Management:** Dynamic reporting via `setLatencySamples` in the audio thread.
- **Resource Management:** Asynchronous background thread for IR loading with lock-free pointer exchange.
- **Dependency Handling:** Explicit "Wire" objects in the data model for sidechain links (e.g., Compressor to Decompressor).
- **DSP Engine:** Utilizing native `juce::dsp` classes, including `IIR::Filter::Coefficients` for EQ tasks.
- **Persistence:** Support full serialization of topology and state (XML-based).
- **Graph Topology:** DAG constraint enforced (no feedback loops).
- **Standalone Configuration:** Store/recall audio hardware settings.

## UI Aspects
- **Main Area:** Retained-mode canvas for visualizing the graph (nodes and wires).
- **Interactions:** Drag-and-drop blocks and connections; context menus for management.
- **Sidebar:** Context-sensitive inspector showing only selected block parameters (sliders/text fields). 
  - **Distortion:** Drive, Tone, Output Level, Curve (dropdown).
  - **EQ:** Frequency, Gain, Quality (Q), Type (dropdown).
  - **Compressor/Decompressor:** Threshold, Ratio, Attack Time, Release Time, Makeup Gain.
- **Palette:** Draggable palette for adding new effect blocks (Distortion, EQ, Compressor, Decompressor, IR).
- **Top Menu:** Access to global settings and device configuration (ASIO/Input/Output).

## Testing Decisions
- **Testing Goal:** Focus on testing external behaviors and interface contracts, avoiding coupling to implementation details.
- **Modules to Test:** 
    - Graph model connectivity and validity logic.
    - DSP effect classes (in isolation).
    - Asynchronous IR loading state management.
    - Controller interactions with the Model.
