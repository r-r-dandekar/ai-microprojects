# PRD: Parardha Technologies Website

**Sources:** website/003-decisions.md, website/004-style-decisions.md, 001-intent.md, website/001-intent.md

---

## Problem Statement

Parardha Technologies is a new AI consulting practice targeting SMBs. It currently has no web presence. Potential clients have no way to discover the business, understand its services, or initiate contact.

---

## Solution

A single-page brochure website hosted on Netlify. It introduces the brand, explains the services and engagement models, and provides a contact form that stores submissions in Supabase. No user login required.

---

## User Stories

1. As a potential client, I want to land on a page that immediately communicates what Parardha Technologies does, so that I can decide in seconds whether it's relevant to my business.
2. As a potential client, I want to see the company tagline and a clear call-to-action, so that I know what to do next.
3. As a potential client, I want to scroll through the page to learn more, so that I don't have to navigate away from the homepage.
4. As a potential client, I want to see a list of services clearly described, so that I understand what AI consulting help is available.
5. As a potential client, I want each service described in a scannable format, so that I can quickly assess relevance without reading dense text.
6. As a potential client, I want to understand how I can engage with Parardha Technologies commercially, so that I know what kind of commitment is expected.
7. As a potential client, I want to see the three engagement models (Hourly, Retainer, Project-Based) explained, so that I can identify which suits my situation.
8. As a potential client, I want to know who each engagement model is best suited for, so that I can self-select before reaching out.
9. As a potential client, I want a contact form that is easy to fill out, so that I can reach out without friction.
10. As a potential client, I want to know when I can expect a response after submitting the contact form, so that I'm not left uncertain.
11. As a potential client, I want the website to work well on my phone, so that I can browse it during my day without needing a desktop.
12. As a potential client, I want the page to feel professional and modern, so that I trust the credibility of the consultant.
13. As a potential client, I want the navigation to take me directly to each section, so that I can jump to what matters to me.
14. As a business owner, I want all contact form submissions stored in a database, so that I have a queryable record of all leads.
15. As a business owner, I want the website to be hosted reliably for free, so that I have no running costs while the business is getting started.
16. As a business owner, I want the site to reflect my brand colors and typography, so that it is consistent with my brand identity.

## Implementation Decisions

### Modules

1. **Page Shell**
   - Single HTML file containing all sections
   - Sticky top navigation bar with anchor links to each section
   - Smooth scroll behavior on anchor navigation
   - Intersection Observer API triggers fade-in animation as sections enter the viewport

2. **Hero Section**
   - Displays the tagline: "Scale Infinitely, Win Strategically."
   - Subheading clarifies the value proposition in one sentence
   - Single CTA button: "Get in Touch" — anchor links to the Contact section

3. **What We Do Section**
   - Six cards, each with: an icon, a short title, and a one-line description
   - Content drawn from the six service points in 001-intent.md:
     - Where AI helps
     - Build, buy, or partner decisions
     - Feasibility & ROI
     - Navigating the vendor landscape
     - Strategic roadmapping
     - Risk assessment
   - Cards laid out in a responsive grid

4. **Work With Us Section**
   - Three cards: Hourly, Retainer, Project-Based
   - Each card describes: the engagement model, who it suits, and how to get started
   - No prices listed — all cards direct to the Contact section
   - Cards laid out in a responsive grid

5. **Contact Section**
   - Form fields: Name, Email, Message
   - Submit button
   - On submit: data sent to Supabase via the Supabase Client module
   - Success state: form replaced with a confirmation message
   - Error state: inline error message if submission fails
   - Text below the form: "I'll respond within 2 business days."

6. **Supabase Client**
   - Initializes the Supabase JS SDK with project URL and public anon key
   - Exposes a single async function: `submitContactForm({ name, email, message })`
   - Returns `{ success: true }` on success, `{ success: false, error }` on failure
   - All Supabase credentials stored in a config file or environment variables — never hardcoded inline

7. **Stylesheet**
   - Font: Space Grotesk (loaded from Google Fonts)
   - Background: dark charcoal (#1a1a2e or similar)
   - Primary accent: #FF9966 (Coral-Orange) — used for CTAs, highlights, hover states
   - Body text: white / light grey
   - Mobile-first, responsive via CSS Grid and media queries
   - Fade-in animation class applied by the Intersection Observer

### Architecture
- No build tools, no bundler — plain HTML, CSS, and JS files
- Supabase JS SDK loaded via CDN
- Deployed to Netlify via drag-and-drop or Git integration

### Supabase Database Setup

The following steps must be completed before the contact form will work:

1. Create a free account at supabase.com
2. Create a new project (choose a region close to your users)
3. In the Supabase dashboard, go to **SQL Editor** and run the following to create the contacts table:

```sql
CREATE TABLE contacts (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL,
  email text NOT NULL,
  message text NOT NULL,
  created_at timestamptz DEFAULT now()
);
```

4. Go to **Project Settings → API** and copy:
   - **Project URL** (e.g., https://xxxx.supabase.co)
   - **anon / public key**
5. Paste these into the site's config (a `config.js` file — do NOT commit this file to a public repo)
6. In the Supabase dashboard, go to **Authentication → Policies** and ensure Row Level Security (RLS) is enabled on the `contacts` table
7. Add an INSERT policy to allow anonymous inserts:

```sql
CREATE POLICY "Allow anonymous inserts"
ON contacts
FOR INSERT
TO anon
WITH CHECK (true);
```

8. Confirm the policy is active before testing the contact form

## UI Aspects

### General
- Dark charcoal background throughout the full page
- Coral-orange (#FF9966) used exclusively for: CTA buttons, section accent lines, hover states, and card borders or highlights
- All body text in white or light grey for contrast
- Space Grotesk font across all text elements
- Consistent section padding (generous vertical spacing between sections)
- Max content width capped (e.g., 1100px) and centered on wide screens

### Navigation Bar
- Sticky — stays at the top on scroll
- Background: slightly darker charcoal or semi-transparent with blur
- Links: Home, What We Do, Work With Us, Contact
- Active link highlighted in coral-orange
- On mobile: collapses to a hamburger menu

### Hero Section
- Full viewport height (100vh)
- Tagline in large, bold Space Grotesk — coral-orange or white
- Subheading in smaller white text below the tagline
- CTA button: coral-orange background, dark text, rounded corners
- Centered layout on all screen sizes

### What We Do Section
- Section heading centered at the top
- 6 cards in a responsive grid (3 columns desktop, 2 tablet, 1 mobile)
- Each card: icon (top), bold title, one-line description
- Card background: slightly lighter than page background to create depth
- Coral-orange icon color or top border accent

### Work With Us Section
- Section heading centered at the top
- 3 cards in a responsive grid (3 columns desktop, 1 mobile)
- Each card: engagement model name (bold), description, "who it suits" line, CTA directing to contact
- Visual parity with the What We Do cards

### Contact Section
- Section heading and response time text centered above the form
- Form centered, max-width constrained (e.g., 600px)
- Input fields: dark background, light border, white text, coral-orange focus outline
- Submit button: coral-orange, full width of the form
- Success state replaces the form with a confirmation message in coral-orange
- Error state shows an inline message in red below the submit button

### Animations
- All sections start invisible (opacity: 0, slight translate-y offset)
- Intersection Observer adds an `.visible` class when the section enters the viewport
- `.visible` transitions to opacity: 1, translate-y: 0 over ~400ms ease-out
- No animation on the nav bar

### Mobile
- Single column layout throughout
- Nav collapses to hamburger
- Font sizes scale down proportionally
- Cards stack vertically
- Form takes full width

## Testing Decisions

### What Makes a Good Test
Test external behavior only — given an input, assert on the output or side effect. Do not test internal implementation details (e.g., which Supabase method was called internally). A good test breaks when the behavior breaks, not when the implementation changes.

### Modules to Test

**Supabase Client (`submitContactForm`)**

Test the following behaviors:
- Given valid `{ name, email, message }` input, returns `{ success: true }`
- Given a Supabase error response, returns `{ success: false, error }`
- Given missing required fields, returns `{ success: false, error }` without making a network call
- The submitted data matches exactly what was passed in (no mutation or transformation)

**Test approach:**
- Mock the Supabase SDK at the network boundary — intercept the HTTP call, do not call the real Supabase instance
- Use a test runner that works without a build tool (e.g., Vitest with a minimal config, or a simple fetch-mock approach)
- Keep tests colocated with the Supabase Client module

No tests required for the UI sections, stylesheet, or page shell.
